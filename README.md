# Pre-V4 Falsification Ledger

A major purpose of this repository is to record ideas that failed rather than quietly deleting them.

Failures are data.

## 1. Scalar capacity metric — killed

A single scalar capacity field can mimic a Newtonian-looking weak acceleration but does not provide the tensor structure required for relativistic gravity and correct light bending.

## 2. Pure information-distance geometry — killed

Positive-definite Fisher/Bures-style information metrics do not naturally generate Lorentzian causal structure.

Causal order has to enter somewhere more fundamental.

## 3. Exact commuting-projector gravitons — killed

Exact local metric gauge invariants begin at curvature order.

Squaring them naturally generates higher-derivative dispersion rather than the required relativistic `z = 1` behaviour.

The correct target is a protected constraint ideal, not an exact commuting-projector graviton code.

## 4. Naive finite-cell Goldstone construction — killed

The finite-cell construction generated too many low-energy modes and the wrong dispersion structure instead of two helicity-2 modes.

## 5. Total Hilbert-space area law — killed

Forcing the entire physical state space of a bulk region to scale only with boundary area conflicts with the existence of local bulk graviton excitations.

## 6. Numerical near-matches without derived normalization — killed

Attractive numerical coincidences were discarded when the required normalization could not be independently derived.

## 7. Local information-density black-hole trigger — killed

Black-hole formation cannot be characterized by a universal microscopic local-density threshold.

In particular, macroscopic black holes do not exhibit a universal average-density criterion.

## 8. Hand-matched Hermitian MOTS bridge — demoted

A compatibility toy model could be tuned to reproduce a near-zero mode and fold behaviour.

That was not an autonomous derivation.

More importantly, the generic MOTS stability operator contains a drift term and is not generally self-adjoint.

The microscopic target therefore has to be a retarded reduced response, not simply a Hermitian Hessian.

## 9. One-rishon K6 scaling claim — demoted

The one-rishon K6 model required a compensating background doublet.

The sequence was rebuilt using homogeneous even-rishon material.

The softening survived, but the original K6 scaling interpretation was not retained.

## 10. Fold interpretation of the current soft pole — killed

The detuning scan gives:

```math
\chi(t)\sim t^{-1}
```

not:

```math
\chi(t)\sim t^{-1/2}
```

The current pole is therefore a sector crossing, not the desired nonlinear fold.

# Technical Specification Supplement

## Microscopic setup

The project studies an explicit finite-dimensional quantum-link/rishon system on abstract graph topologies.

A schematic microscopic Hamiltonian takes the form:

```math
H_{\mathrm{micro}}
=
H_F
+
H_H
+
H_B
+
H_{\mathrm{exch}}
+
U_G
\sum_x
\frac{1-G_x}{2}
```

with constrained rishon/link degrees of freedom and gauge-covariant interactions.

The homogeneous sequence uses two co-located SU(2) fundamental doublets per link projected into the symmetric triplet representation.

This removes the need for the compensating background doublet that complicated the earlier one-rishon K6 calculation.

---

## Physical response sector

Bare operators that violate the exact gauge projection cannot be used as physical response probes.

The response calculation therefore works with gauge-compatible composite or covariant bridge operators inside the physical sector.

A representative covariant bond structure is:

```math
B_x^\dagger
U^F_{xy}
B_y
U^{H\dagger}_{xy}
+
\mathrm{h.c.}
```

The precise implementation is preserved in the archived computational code.

---

## Matrix-free computation

The larger calculations are not performed by constructing the full dense Hamiltonian.

Instead, the action of the Hamiltonian and response operators is implemented directly on vectors.

This permits Lanczos, Conjugate Gradient and related Krylov methods to operate in spaces that would otherwise be prohibitively expensive.

The guiding rule is:

> **Never build the monster if you only need to know what the monster does to a vector.**
