
# Reproducibility guide

## Environment

The final pass was run with:

```text
Python 3.13.5
NumPy 2.3.5
SciPy 1.17.0
```

Install:

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
python -m pip install -r requirements.txt
```

Run the lightweight consistency suite:

```bash
python run_all_tests.py
```

This validates the checked-in states/results and does not recompute the expensive searches.

## Authoritative state files

```text
data/states/autonomous_N128.npz
data/states/autonomous_N216.npz
data/states/autonomous_N344.npz
data/states/generic_initial_N344.npz
```

The `data/legacy/` directory contains historically useful states that are explicitly **not** evidence for unrestricted autonomous nucleation because they descend from the old hard-radius proposal code.

## Core final-pass commands

Run from the repository root.

### Three-size geometry metrics

```bash
python scripts/three_size_metrics.py \
  data/states/autonomous_N128.npz \
  data/states/autonomous_N216.npz \
  data/states/autonomous_N344.npz
```

This writes `results/three_size_metrics.json`.

### Abelian/Cayley adversary scans

The saved scans used 10,000 generator triples per factorization family:

```bash
python scripts/cayley_scan.py 128 10000
python scripts/cayley_scan.py 216 10000
python scripts/cayley_scan.py 344 10000
```

These are stochastic scans, not exhaustive proofs over all Cayley graphs.

### Physical rank-4 audit

```bash
python scripts/rank4_keff_autonomous.py data/states/autonomous_N128.npz 16000 101
python scripts/rank4_keff_autonomous.py data/states/autonomous_N216.npz 16000 102
python scripts/rank4_keff_autonomous.py data/states/autonomous_N344.npz 16000 103
```

The exact historical seeds used to produce the checked-in JSON outputs should be treated as recorded-result provenance rather than a claim of seed independence. Repeats with fresh seeds are encouraged.

### Global H_mix feasibility

```bash
python scripts/hmix_global_corrected.py data/states/autonomous_N216.npz 16000 2101
python scripts/hmix_global_corrected.py data/states/autonomous_N344.npz 16000 3441
```

### Local H_mix radius-4 witness search

Representative usage:

```bash
python scripts/hmix_R4_witness.py \
  data/states/autonomous_N344.npz \
  32 4 results/hmix_R4_example.json \
  16000 3000 1
```

A successful subset is a constructive witness that the full radius-4 move cone is feasible. A failed random subset is not a proof of infeasibility.

### Cycle-space spanning length

```bash
python scripts/cycle_rank_autonomous.py \
  N128=data/states/autonomous_N128.npz \
  N216=data/states/autonomous_N216.npz \
  N344=data/states/autonomous_N344.npz
```

### Soft all-face curl gap

```bash
python scripts/softcurl_dense.py data/states/autonomous_N128.npz N128 7
python scripts/softcurl_dense.py data/states/autonomous_N216.npz N216 7
python scripts/softcurl_dense.py data/states/autonomous_N344.npz N344 8
```

### Exact finite combined quantum sectors

Generic relation-condensation sector:

```bash
python scripts/quantum_hypercube.py 64 10 64001
python scripts/quantum_hypercube.py 128 9 128001
```

Basin-side sector:

```bash
python scripts/quantum_hypercube_basin.py data/states/autonomous_N128.npz 9 991
```

These are exact finite subspaces generated by commuting/disjoint legal 2-switches. They are not a diagonalization of the full graph configuration space.

## Important runtime notes

- `cayley_scan.py`, rank-4 sampling, radius-4 H_mix enumeration, and dense curl calculations can take significant CPU/memory.
- Results depend on stochastic candidate sampling where noted.
- `N=344` radius-4 move cones can contain very large numbers of legal local rewrites; witness scripts intentionally use subsets to obtain constructive feasibility certificates.
- Saved result JSON may contain optimizer status flags that are conservative even when the final residual is numerically near zero; inspect the residuals and constraints, not only a single optimizer boolean.

## Provenance

Earlier continuation/checkpoint packages are retained in `archive/`. They contain historical scripts, logs, and states, including failed and superseded approaches. They are useful for forensic review but should not override the frozen candidate or final-pass ledger.
